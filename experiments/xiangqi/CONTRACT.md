# 三模式共用产品与验收契约 v1

人类意图来源：当前聊天要求安装本项目的集权、分权、组合开发技能，分别依其架构实现象棋游戏客户端，进行效果对比。以下平台与功能是为完成示例而作的工程选择，不声称是用户逐项指定。

## 可比范围
- 三个独立浏览器客户端，原生 HTML/CSS/JavaScript ES modules，无外部依赖、网络素材、登录或生产服务。中文界面，桌面主视图兼容 390px 窄屏。
- 相同核心功能：标准 9×10 棋盘、32 子初始布局、红先行、本地双人轮流、选子和合法落点、吃子、非法走法反馈、将军提示、将死及困毙判负、终局停止走棋、悔棋、重新开始、翻转棋盘、走棋记录。
- 实现车直线、马腿、象眼与不过河、士/将九宫、炮隔子吃子、兵卒过河、将帅照面、不能自陷将军。不实现比赛长将/长捉裁定、联网、AI、计时竞赛、音效或存档；界面明确是本地双人。
- 一份需求与外部测试，三个实现互不复制代码、不读取另外两个实现。每组一个产品实现者，其他角色按对应技能发挥职责，模型继承主会话设置。
- 产品路径分别为 `experiments/xiangqi/centralized/`、`decentralized/`、`combined/`。共用测试、入口和报告置于上一级。不可修改技能来源、已有项目文件或别组产物。

## 可测试引擎接口（engine.js）
`board[y][x]` 为 null 或 `{side:'red'|'black', type:'rook'|'horse'|'elephant'|'advisor'|'general'|'cannon'|'soldier'}`；0<=x<9，0<=y<10。黑在上、红在下。坐标 `{x,y}`。

必须具名导出：
- `createInitialBoard()` → 新棋盘。
- `isInCheck(board, side)` → boolean（按棋子攻击几何和阻挡判断）。
- `getLegalMoves(board, from, side)` → `{x,y}[]`，拒绝非本方/越界来源，只包含不会使己方被将的落点。
- `applyMove(board, from, to, side)` → `{ok:boolean, board, reason?:string}`。纯函数，不修改输入；非法不变；合法返回独立棋盘。
- `getGameStatus(board, sideToMove)` → `{over:boolean, winner:null|'red'|'black', reason:string, inCheck:boolean}`；无合法着（含困毙）判负；缺将判负。

产品至少有 `index.html`、`styles.css`、`app.js`、`engine.js` 和 README。app 管理轮次、历史、翻转等状态，引擎不依赖 DOM。上级 package.json 设置 type=module。

## 设计 brief
安静、适合专注对弈的中式棋室。以棋盘为视觉中心，米纸/木色棋面，深墨文字与朱红红方；使用本机中文字体回退。桌面棋盘旁有轮次、操作和棋谱，窄屏上下排布。交互需有可见焦点、中文可访问名称、状态提示，选中/合法落点不能只靠颜色。禁止营销页、假统计及把治理流程塞入玩家操作；仅页眉小字注明实验版本即可。各实现者可在相同 brief 下独立选择具体布局与代码结构。

设计检索：已实际运行 UI UX Pro Max `board game calm desktop --design-system`。命中游戏材质/绿色金色方案，但其营销布局、3D 和英文字体不适合本产品，未照搬；采用低动效与键盘焦点建议，并由产品意图确定中式棋室风格。

## 验证门槛
1. 三组均通过共用 `node --test tests/acceptance.test.mjs`（通过环境变量 XIANGQI_MODE 选择组别），不得改共同测试掩盖失败。
2. 组内补充有意义规则测试；独立审查必须读取代码、重跑检查、绑定产品文件 SHA-256，保留失败及修复前报告。
3. 实际浏览器检查开局、走棋、悔棋、重开、翻转、非法提示及桌面/窄屏无横向溢出；浏览器不可用须标明未验证，不假报 PASS。
4. 集权需要独立审查与下属监督后指挥者接受；分权需要裁衡者审查规则意图与产品；组合需要内层审查/监督/接受及外层独立裁衡。
5. 只交付本地可运行成果及本地预览，不推送、不对外部署，不声称 RELEASED。

## 真实能力与比较限制
共享工作区和工具权限，仅流程上的角色隔离，不是强制安全隔离。原始工具结果和各角色自行写的记录是证据；token/费用无法逐组精确计量则记 unknown。记录墙钟时间、角色人数、测试数、首次审查发现、修复轮次、代码规模；并发运行受调度和资源干扰，单次示范不能证明普遍优劣或做因果排名。

执行额度：每组一个实现者；最多三轮正式审查（初审+两次重审）；单组运行自角色建立起以 60 分钟为本轮自主执行边界（非声称用户付费预算），保留检查/交付时间。到边界仍有失败，交付真实待审成果。不得派生未登记角色。
