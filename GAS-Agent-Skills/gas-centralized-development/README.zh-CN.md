# 集权开发模式技能 · v3

入口 [SKILL.md](SKILL.md)，规则 [运行协议](references/protocol.md)。技能显示名称为“集权开发模式技能”，指挥者等角色名称及职责保持不变，目录/name保持 `gas-centralized-development`，机器身份字段仍用 `coordinator`。

## 角色与证据

所有模式角色均由真实子 agent 承担，执行者数量可由用户指定为 N≥1；默认 N=1，是指挥者、执行者、审查者、监督者共 4 个独立身份，实际团队为 N+3 个真实子 agent。每名执行者绑定独立任务与允许路径，承担该任务开发、测试验证代码编写／修改及验证执行。主会话不占席，只展示进展与承接人类交互；宿主必要时按已确认名单或具名角色指令机械转接创建、通知、回执，不决定业务派工优先级，也不实现、测试、裁决、验收或发布。子 agent 能力缺失或必需成员未就绪时保持 `WAITING_FOR_TEAM`，等待补齐，不能由主会话接任。模型、推理强度、职责仍由人类按 AGENT-01 确认；原等待、全员就绪及服务档位继承规则继续适用。

指挥者管理执行者、审查者和监督者，并承担集成发布。审查者主要接收执行者与监督者输出，独立分析精确代码与原始证据；可只读检查和复跑已有命令，不编写／修改测试验证代码，补证由指挥者派给具名执行者。监督者核对执行者、审查者的行为是否符合指挥者意图，检查规则遵守和不安全行为，监测全部下属 agent 状态、板卡电压电流和运行、软硬件异常，受指挥者调度并向其汇报，不监督指挥者。监测权限、工具、阈值或读数未知时记录实际缺口；无监测手段不能保证安全，暂停须既有有效限定授权。指挥者唯一的角色监督者是人类；平台权限和真实技术门禁依旧有效。

技术验证、下属监督、管理决定分开留档。监督不能代替技术测试或独立审查。指挥者亲自修改实现时，仍须取得另一真实审查者或人类对精确产物的技术验证；这不把监督者变成指挥者的上级。监督者无默认暂停他人任务权限；有效限定委托下才能最小暂停，恢复、终止、重派仍由指挥者决定。

原七份JSON保持 `schema_version=3`、`example_only=true`，用可空 `runtime_evidence_ref` 接入独立版本的共同附表。未知身份、空证据、未签发指令不构成已建立能力。示例要求接受前具备监督覆盖；实际调整要求须来自有效契约，不能因环境不足就默认为不需要。

指挥者主动拆分尽可能多的就绪独立任务，在预算与并发能力内并行；路径冲突、共享板卡烧录和在线调试使用具名资源锁，仅冲突动作串行。run.execution_team记录人数来源、真实执行者与任务／路径／验证归属；保留默认最低4人的旧字段，实际名单按N+3核齐。扩展监测字段保持原三项coverage兼容；监测另记录采样／评估时刻、新鲜度规则及有效窗口，旧读数过期或依据未知不可写安全。单通道失效阻塞受影响硬件动作，监督身份或独立履职整体能力缺失才关闭全队屏障。执行者失联替换须撤销旧指令／暂停委托、核对旧文件与设备控制停止或真实撤权，未知设备锁不凭超时释放，再重绑定开发验证归属并按原AGENT-01恢复全员就绪。静态检查只核对示例结构，不验证读数真实性或监测可用性。

指挥者用运行契约的任务索引和任务契约的进展账本记录最后实际进展、连续无进展原因、有界重规划与下一动作。业务预检在 `TEAM_READY` 后、批量制作前进行，核对实际输出与环境；仍有效的旧预检可复用。指令分别记录发送、接收、开始与完成，恢复按实际宿主能力核对检查点和副作用，`UNKNOWN` 不直接重发。技术执行、技术结论、风险接受、管理裁决、监督和实际交付保持分离；已执行但输出不可判定记执行完成／结论不确定，不改写为未执行。

## 使用与迁移

明确要求Agent读取本目录SKILL.md，并说明真实项目和目标。存放文件不自动完成宿主发现、注册或激活；Skill不实现运行器、权限隔离、命令队列或生产门禁。

保留v1/v2记录；已有任务先到安全点，核对旧integrator行动、回执、幂等键与外部状态，由当前指挥者接管未完成交付职责，不能自动重发。v2技术验证不是v3监督记录；建立真实监督身份和覆盖。旧授权可在核实仍适用后复用，角色变更不产生额外权限。

v3 的角色和原记录兼容性保持不变；本次按共同策略接入独立附表，不将旧记录自动重写为新验收结果。完整包根校验器支持v3；候选完整性以实际运行校验结果为准。旧备份清单保持原样，不把旧清单不匹配当成现包损坏。

## 检查

Python 3.9+，只使用标准库；将 `py -3` 换成本机可用Python命令即可。

```powershell
py -3 -B .\scripts\validate_skill.py
py -3 -B -m unittest discover -s tests -v
```

完整包根目录另运行 `py -3 -B .\verify_bundle.py` 及根 `tests`。校验器检查示例结构、缺省状态、链接和关联，不是实际运行记录的安全执行器。

从本技能目录调用证据工具时，将 `DIR`、`FILE` 替换为实际项目路径；清单、附表和日志保存在候选目录外：

```text
python scripts/gas_runtime.py manifest --candidate DIR --output FILE
python scripts/gas_runtime.py verify --candidate DIR --manifest FILE
python scripts/gas_runtime.py assess --candidate DIR --manifest FILE --record FILE
```

stdout 为 JSON；退出 0 表示所请求机械条件成立，1 表示未通过，2 表示输入非法。`technical_evidence_ready` 不能证明产物语义正确、真实独立身份或发布权限，不能替代指挥者裁决及原有门禁。附表字段与复用／失效规则以 [运行证据说明](references/runtime-evidence.md) 为准。

v3 的历史真实子Agent文字决策探针、原文、无Skill对照、变异测试和只读审查记录保存在项目 `update-audit/commander-v3-20260928/`。2026-10-01 的增量基线、检查和真实文件故障实验记录保存在项目 `output/strategy-upgrade-2026-10-01/`，以实际记录为准；文字判断与机械实验分别报告。它们不等于48场景在真实项目中全部执行，也不证明多Agent协作性能、强制权限隔离或生产可靠性。场景模板NOT_RUN不写成PASS；真实运行结果单独存放。详见完整包VALIDATION.md和审计报告。
