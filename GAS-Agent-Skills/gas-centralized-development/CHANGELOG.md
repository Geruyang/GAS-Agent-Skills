# 变更记录

## 执行与验证职责、并行和监测 · 2026-10-04

执行者可由用户指定 N≥1，默认一名并保留4人兼容示例，实际团队N+3；每人具名绑定独立开发任务及验证代码与执行。审查者主要接收执行者和监督者输出，只读独立分析、核对原始证据或复跑已有命令，不编写／修改测试验证代码；缺口由指挥者派给具名执行者。

监督扩展全部下属状态、板卡电压电流和运行、软硬件异常观测，保留指挥意图核对与既有暂停授权边界；能力、阈值、读数未知如实记录，无监测不能保证安全。指挥者主动拆分就绪独立任务并行，路径、板卡烧录／调试资源锁只限制冲突动作。补齐遥测采样／评估时刻、新鲜度规则与有效窗口；过期／未知不可写安全。普通执行者失联替换先撤销旧控制、核对文件和设备实际停止／撤权，再重绑职责并恢复全员就绪；单通道覆盖缺口与整体监督能力缺失分别处理。schema3、原三coverage键、AGENT-01、独立审查与精确产物门禁均保留；新增14个待运行场景和静态负例，不宣称真实团队或硬件实测。

## 全角色子 agent 承载 · 2026-10-02

指挥者、执行者、审查者、监督者默认由 4 个身份互不相同的真实子 agent 承担，主会话不占角色席位，仅展示进展、承接人类交互与宿主必需的机械转接。移除无子 agent 时单执行者兼任的降级路径，必需角色或能力缺席时保持 WAITING_FOR_TEAM；区分角色缺席与在席但审查／监督证据未完成。

保留 AGENT-01 的人类模型、推理强度与职责选择、等待及服务档位规则；指挥者原有业务裁决、作者及交付职责和独立验证门槛不变。原 run schema 3 保持兼容，主会话不能因持有工具而代行业务或继任指挥者。

## 运行证据增量 · 2026-10-01

在原 v3 协议和七份 schema 3 模板上增加共同运行证据附表引用，附表使用独立版本；保留技术验证、管理裁决、监督及交付原记录。补充分开治理模式与执行拓扑、TEAM_READY 后的关键能力小样本、有效旧预检复用、候选清单与证据绑定，以及风险接受不能改写技术事实的规则。

增加指挥者任务索引、实际进展账本、连续无进展原因与有界重规划；统一指令补充发送、接收、开始、完成和检查点证据。恢复依据实际工具语义，未知副作用先查询，不盲重发。指挥者亲自交付、监督者仅监督执行者和审查者、AGENT-01、全员就绪及服务档位继承规则保持不变。

新增离线证据工具与独立附表由共同模块提供；机械核对不产生授权，不替代技术判断或治理裁决。新验证记录保存在项目 `output/strategy-upgrade-2026-10-01/`；旧 FAIL／NOT_RUN、历史版本和未执行场景不改写，不宣称三种治理模式性能已经得到对照证明。

## 名称更正 · 2026-09-28

技能名称改为“集权开发模式技能”。指挥者、执行者、审查者、监督者的名称、职责及全部流程含义保持不变；机器标识与目录不变。

## v3 · 2026-09-28 · 指挥者

显示名称改为指挥者，机器标识与目录不变。取消独立集成发布角色，相关行动由coordinator身份承担；新增受指挥者控制并向其汇报的supervisor，只覆盖执行者与审查者，指挥者仅由人类角色监督。

七份示例升级schema_version=3，新增监督报告、监督范围/覆盖/限定暂停委托、独立验证与监督分离、监督缺失状态和交付接管迁移规则。保留精确版本、真实授权、独立技术验证、任期和幂等门禁。

新增16个场景，共48个。加强校验器反例、嵌套结构检查与损坏文档处理；当前真实验证结果见包级VALIDATION.md及审计记录，不修改示例场景的NOT_RUN状态。

## v2 · 2026-09-28 · 中枢

显示名称从“GAS 集权开发模式”改为“中枢”，保留目录和机器标识。

将集中派工扩展为执行、审查、集成发布的统一指挥。中枢新增明确的审查任命／替换、补证／复核、普通建议取舍和交付时机决定权；内部接口等技术变更按实际委托范围自行裁决，不一律升级用户。

将验证记录与中枢管理决定分开，新增统一指令、管理决定和交付指令模板；保留未批准、未签发、未运行的安全默认值。中枢作为作者时可在真实独立验证后作管理接受，不可自作独立审查。

任期校验、撤销、有效期、预算与防重要求扩展到全部角色；禁止审查者任意阻塞，也禁止换人刷通过、删改证据或绕过硬门槛。发布依据有效中枢指令、相应授权与精确产物验证。

添加 v2 迁移规则、静态校验器与反例回归测试，压力场景增至 32 个。场景仍标 NOT_RUN，不能视作已完成的真实 Agent 评测。
