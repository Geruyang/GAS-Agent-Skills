## 1.3：客户端子 agent 列表优先

三个技能的 AGENT-01、协议及 Fast 指南均明确：默认通过 Codex 原生通道创建子 agent，并在当前任务的子 agent 列表中展示。需用 CLI 托管时先弹窗说明角色、理由、已尝试路径和管理差异；不同意则继续排查原生列表路径，只有取得答复且有证据确认适用列表方式均不可行、CLI 可行时，才按用户明确要求的条件性兜底执行，并在客户端提前披露。未回复、单次失败或 Fast 配置困难均不授权切换；用户明确禁止任何 CLI 时不得兜底。

运行位置证据与 CLI 同意／兜底记录纳入全员就绪检查。正常调用终端工具执行构建或测试不属于 CLI 托管 agent。规则不授予绕过宿主权限、并发或预算限制的权力，也不声称可把独立 CLI 会话强制显示到原生列表。

本机实际执行：三份运行位置规则一致，TOML 示例可解析；包静态检查 **424/424**、集权检查 **212/212**、包回归测试 **32/32**、集权回归测试 **58/58** 全部通过。本次未新建原生或 CLI 子 agent，未实测列表显示、CLI 许可弹窗或拒绝后兜底流程；本次交付是流程规则与文档更新。

## 1.2：持续等待与服务档位修正

依据用户反馈，修正三个技能的 AGENT-01：异步弹窗发出后以可唤醒的短周期等待保持任务活跃，默认预留至少 30 分钟思考时间，未答复则继续等待；配置、职责及修改后确认均适用。等待期间不结束任务、不推进其他工作；保留宿主强制中断的能力边界与恢复方式。用户报告过早结束是反馈证据，本次未复现客户端界面行为。

将“速度”选项改为“服务档位：默认 / Fast”。用户所说的“1.5 倍速”对应 Fast，“非 1.5 倍速”对应默认。依据 [Codex 配置说明](https://learn.chatgpt.com/docs/config-file/config-reference) 核对 fast 到请求值 priority 的映射，并区分选择、请求和实际生效的档位；接口不支持的字段不得伪造。

本机实际执行：包静态检查 **412/412**、集权检查 **209/209**、包回归测试 **32/32**、集权回归测试 **58/58** 均通过。未运行真实 30 分钟弹窗交互、子 agent 创建或服务档位生效测试；本次修改的是技能流程规则，不是客户端程序。已有压力场景仍为 `NOT_RUN`。
