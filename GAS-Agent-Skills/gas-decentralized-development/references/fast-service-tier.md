# Fast 服务档位：独立 Agent 配置与核验

创建 Fast 子 agent，或创建工具没有服务档位参数时，读取本说明。**工具没有参数，不等于宿主不支持 Fast；必须检查独立自定义 agent 配置路径后才能判定能力不足。** 配置落地仍遵守人类的模型／强度／档位／职责选择、宿主文件权限和全员就绪规则。

## 配置路径

1. 核对当前宿主的自定义 agent 加载方式、可选角色、模型和配置优先级。项目范围可使用 `.codex/agents/<name>.toml`，个人范围可使用 `~/.codex/agents/<name>.toml`；路径相对实际使用该技能的项目／用户目录，不是技能包目录。
2. 优先为本轮已确认角色使用独立、无冲突的配置文件，保存模型、推理强度、服务档位和最终职责。保留其他会话与已有角色设置；不得为了一个子 agent 改动全局默认服务档位。配置文件是正式配置层，提示词中写“请用 Fast”不能代替它。
3. 宿主识别该角色后，在创建调用中用其角色名选择对应配置，例如接口支持时指定 `agent_type`。不能只把配置路径写进任务文本，也不能继续选内置 `default`／`worker` 并假定自定义配置会自动套用。配置热加载、重载或新会话需求以当前宿主为准；未识别时先解决加载问题，不静默使用默认角色。
4. 模型和推理强度显式覆盖须与最终人类选择一致。官方当前说明中，自定义文件显式指定的 `model`、`model_reasoning_effort` 会覆盖创建阶段解析的值；不要只改 spawn 参数却保留冲突的文件值。使用自定义角色时还须遵守创建工具的历史继承限制。
5. 创建成功后核验目标会话回执，再登记该成员就绪。其他成员未全部就绪前仍不启动业务工作。

## 独立 TOML 示例

以下是用户反馈中监督者的配置组合，仅作写法示例，不替代本轮弹窗选择。文件可命名为 `.codex/agents/gas_supervisor_fast.toml`；`name`、`description` 和 `developer_instructions` 是独立自定义 agent 文件的必要字段。

```toml
name = "gas_supervisor_fast"
description = "GAS 下属行为监督者，仅监督执行者与审查者。"
model = "gpt-6-luna"
model_reasoning_effort = "high"
service_tier = "fast"
developer_instructions = """
按本轮人类确认的范围监督执行者与审查者，向指挥者报告事实。
不监督指挥者，不代替技术审查，不擅自改代码或发布。
创建后仅确认身份、配置与职责，回复就绪并待命。
收到与本轮完整名单和职责版本一致的全员就绪通知后才开始工作。
"""
```

`service_tier` 是该文件顶层的配置键，不放进职责字符串。把实际确认的职责与任务边界填入文件及派工消息，不因采用示例改变原模式角色关系。

若宿主使用 `config_file` 角色注册方式，在对应项目／用户 `config.toml` 中按需添加独立角色声明；相对路径从声明它的配置文件解析。不要覆盖已有配置，也不要同时建立冲突的重复角色：

```toml
[agents.gas_supervisor_fast]
description = "GAS 下属行为监督者，使用已确认的 Fast 配置。"
config_file = "agents/gas_supervisor_fast.toml"
```

这段角色注册只在当前宿主需要并支持时使用；独立文件已被发现时不必额外注册。宿主写入权限、项目受信状态和配置加载范围仍须核对。若配置路径不可写或宿主确实不支持，报告具体阻塞，不把“spawn 没有 service_tier”作为唯一理由。

## 回执判定：不要混淆三层证据

| 证据 | 可得出的结论 | 不应声称 |
| --- | --- | --- |
| TOML 中已写入 `service_tier = "fast"` | 配置意图已保存 | 宿主已加载／当前会话已生效 |
| 宿主返回该目标会话的实际模型、强度、`serviceTier: priority`（或宿主明确等价的 Fast 值） | 该会话的 Fast 配置已获宿主确认 | 每轮请求一定采用 Fast、固定提速 1.5 倍 |
| 某轮请求的服务响应返回实际 `service_tier` | 该轮请求实际采用的档位 | 所有其他轮次也相同或满足固定耗时比例 |

收到匹配本轮选择的宿主会话回执后，记录会话身份、来源和字段，解除“仅见配置意图”的阻塞；无需继续索取不存在的创建参数或测速证据。只有任务本身要求逐请求核验时才额外索取请求级回执。子 agent 自述“我是 Fast”、配置文件回显或主会话自身的档位不算目标子会话宿主回执。

回执不匹配时，排查实际选择的角色、文件路径、加载状态、配置覆盖顺序和模型支持情况；修正配置后按宿主支持方式应用并重新读取目标回执。仍无法确认则记录“会话档位未验证”，不假装成功，也不擅自更换人类选择。配置变更不能假定会追溯作用于已创建会话或在途请求。

## 已有用户反馈与证据边界

用户报告监督者通过独立配置获得宿主回执：`gpt-6-luna`、`high`、`serviceTier: priority`。这支持该用户当次会话的 Fast 配置已获宿主确认，解决了此前只检查创建参数造成的误判。此案例是用户提供的运行反馈，本次技能维护未读取原始回执，也未重新创建该会话；不能把它冒充本次实测或所有环境的保证。

## 官方依据

- [自定义 agents](https://learn.chatgpt.com/docs/agent-configuration/subagents)：独立文件目录、必需字段、作为子会话配置层加载和模型／强度优先级。
- [Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)：`service_tier = "fast"` 映射到请求值 `priority`，以及 `agents.<name>.config_file`。
- [OpenAI Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)：请求与响应档位的区别；服务档位不承诺每轮固定 1.5 倍提速。
