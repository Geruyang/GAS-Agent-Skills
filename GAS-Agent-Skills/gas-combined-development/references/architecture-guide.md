# 组合开发模式：架构与 Codex 使用说明

内层执行者数量 **N>=1，可由用户指定，默认N=1**。完整配置为 **N+5个独立治理子agent + 1个主会话，共N+6个会话**；默认仍为 **6 个独立治理子 agent + 1 个主会话**。主会话显示进展、承接人类交互和必要的机械转接，不担任治理角色。历史图片采用旧角色承载与人数口径，已取消其现行指导地位；以下文字与协议为准。

## 当前 Skill 架构

**外层执行者与内层指挥者是同一个子 agent、同一任期，只占一个治理子 agent 席位。** 外层立规者、执行者／指挥者、裁衡者，加N名具名内层执行者、审查者、监督者，共N+5个独立子 agent。内层人数可配置，桥接席仍唯一；每名执行者独立承担分配模块开发与验证。外层立规者制定规则和验收标准，裁衡者独立检查规则是否忠实于用户意图、成果是否满足有效规则；执行者在这些边界内自主组织实施。外层三方平级，宿主工具树上的父子关系不改变治理权力。

内层由这个执行者以指挥者身份管理：每名具名内层执行者编写模块实现及测试／验证代码并提交实际验证证据；审查者接收执行者和监督者输出，独立分析问题与证据覆盖，不编写或修改测试／验证代码。补证任务由桥接席指派具名内层执行者；外层裁衡者同样分析原始输出，不写验证代码，可复跑已有命令和对读证据。监督者持续对照指挥者意图核对全部内层执行者与审查者，报告板卡电压／电流、运行状态、agent工作状态和软硬件异常；未知采样／阈值标记不可测，不伪造安全结论。每条监测记录采样与评估时刻、freshness_rule_ref及有效窗口；无新鲜度依据或采样过期记INCONCLUSIVE／不可用，不写安全。单一遥测缺口只阻塞依赖该通道的硬件动作及门禁；角色身份、通信或独立履职整体能力缺失才关闭全员屏障，原有暂停授权和真实硬阻塞仍有效。监督者不监督指挥者；指挥者作为外层执行席，仍受外层规则与独立裁衡约束。

宿主可以将全部角色子 agent 挂在主会话下，也可以支持桥接子 agent 管理内层的工具关联；两者都须核对真实跨 agent 通道与指令来源。全层TEAM_READY后，桥接指挥者主动尽可能并行所有独立就绪任务；只有文件冲突、真实共享板卡烧录／调试占用、依赖或预算限制约束并行范围，并登记占用者与释放条件。监督可与实现、输出就绪部分审查并行，全员组建／增补屏障仍优先。业务指令、优先级、验收、交付决定和执行均由对应子 agent 负责，主会话只原样转接具名角色的消息、展示带来源的状态，不能代行指挥或改写结论。

交付顺序是：**内层接受 → 准备精确集成候选并完成必要重验 → 外层独立裁衡 → 获准交付。** 最终合并或发布由同一个桥接子 agent 完成，两层引用同一个真实动作和回执。具体规则以 [SKILL.md](../SKILL.md) 和 [组合协议](protocol.md) 为准。

运行时按 [依赖与复用登记](../templates/review-reuse.example.json) 注释共同运行证据中的阶段图：每个节点明确输入／输出引用，每条等待边明确所需输出。外裁准备性风险意见标为 `PREPARATORY`，最终裁衡标为 `FINAL`；最终通过不能成为候选生成前提，准备性意见发现的真实硬阻塞仍须阻止相关动作。

内层查产物及实际验证，外层查目标、规则、覆盖与例外。外裁复用原始材料时逐项核对路径、摘要、候选、条款与环境，并登记核对方法和重跑决定；不能复制内层通过签名，契约要求的全量独立检查仍保留。新候选触发内层、外层和交付影响核对，两层始终引用同一 `action_id`、`idempotency_key` 和真实回执。

## 在 Codex 中实施

可以直接读取文件，也可以完成安装后按技能名称引用；二者均需在启动开发前核实角色、权限、N+5个子 agent 槽位（默认六个）及真实通信能力。下文给出可复制的读取、安装和启动指令。

### 1. 在目标项目中按路径读取

当前文件位于普通项目目录，可以让具备文件访问能力的 Codex 直接读取。三个技能保持同级，组合技能的相对依赖才能解析：

```text
E:/AIProject/GAS/GAS-Agent-Skills/
├── gas-decentralized-development/
├── gas-centralized-development/
└── gas-combined-development/
    └── SKILL.md
```

本方式是让 Codex 读取并执行协议，不代表目录已经加入自动发现列表。当前已有文件可直接使用下面的完整提示词。

### 2. 复制启动指令

替换方括号中的任务信息后，在目标项目聊天中发送：

```text
请读取 E:/AIProject/GAS/GAS-Agent-Skills/gas-combined-development/SKILL.md，
以及其中要求读取的组合协议、同级分权和集权技能及其协议，
按组合开发模式完成【具体开发任务】。

主会话仅显示进展、承接人类交互和必要机械转接，不任任何治理角色。
内层执行者数量：【用户指定N>=1；未指定则1】。
请先核实子 agent 工具、N+5个子 agent 槽位（默认六个）、实际现有占用和跨 agent 通道；
若宿主上限包括主会话，总会话需求为N+6；桥接席始终只有一个。
按 AGENT-01 完成人类配置与职责确认，为外层立规者、外层执行者兼内层指挥者、
外层裁衡者、N名具名内层执行者、内层审查者、内层监督者建立独立子 agent，
登记真实身份、指令来源与职责。外层执行者和内层指挥者是同一子 agent。
宿主可将全部治理子agent挂在主会话下，但业务派工、验收及交付均由对应角色子 agent 负责。
每名内层执行者独立负责模块开发和验证代码；审查者分析执行者及监督输出，外裁独立分析，
两者都不写验证代码；补证经唯一桥接席派给具名内层执行者。
全员就绪后主动尽可能并行独立就绪任务，登记文件／板卡／依赖／预算冲突。
监督持续对照指挥意图报告全部内层下属、板卡电压电流与运行、agent状态及软硬件异常；
未知采样／阈值标记不可测，监控可与实现／审查并行。

允许修改：【文件或模块路径】。
验收标准：【可核验的行为、检查或测试】。
预算与停止条件：【时间、调用次数或其他可核对额度】。
本次仅授权本地修改与测试；合并、部署、发布需另有适用授权。

全员 TEAM_READY 后，先依据已有授权内的限定试验许可验证能力，再正式立约；
随后由角色子 agent 完成实施、内层接受、候选验证、外层裁衡和获准交付。
若缺少角色子 agent 或真实通信能力，保持 WAITING_FOR_TEAM，只继续组建和等待；
主会话不接任任何缺席角色，不用同一会话切换称呼冒充独立角色。
```

### 3. 配置子 agent 并发上限并核实能力

本Skill内层执行者N>=1，由用户指定，默认N=1；需要N+5个治理子agent槽位，含主会话共N+6个会话。完整默认配置需要 **6 个独立治理子 agent，另有 1 个主会话显示进展**。子agent槽位不包括主会话；若宿主统计全部会话，默认上限至少须为七，指定N时至少为N+6。该要求不是所有 Codex 环境的默认上限。Codex 的单会话子 agent 并发上限可以配置。

在项目的 `.codex/config.toml` 中添加或更新以下内容；若已有 `[agents]` 段，在该段内修改此键，不重复创建同名段：

```toml
[agents]
max_concurrent_threads_per_session = 16
```

`16` 是此配置示例中的子 agent 上限，不包含主会话，也不表示必须创建 16 个子 agent。本 Skill 默认需要六个治理子 agent，指定N时需N+5个；主会话另行展示进展。启动时核实配置已经生效、多 agent 工具可用、实际运行限制和现有占用；若多 agent 被显式禁用，还需按实际环境启用。配置不足或尚未生效时据实报告并等待，不将文件中的数值当作已经验证的可用能力。[OpenAI：Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

以上为配置示例，不能作为实际 `.codex/config.toml` 已修改或已生效的证据。

### 4. 检查过程与结果

主会话依据角色子 agent 的原始记录，展示N名内层执行者和N+5个治理子agent身份、分工／资源／验证归属、有效契约与版本、精确候选、内层技术审查与监督事实、外层裁衡结论和实际交付回执；展示身份单列，不将主会话写入治理角色。运行记录保存到目标项目内 `.gas/runs/<run-id>/` 或已获准的任务系统；`run-id` 是实际运行标识，不把尖括号当作 Windows 目录名。

分别报告自测、内层接受、外层验收、合并和发布状态。没有执行的步骤写“未执行”；缺独立审查或监督时保留等待状态。已有适用授权可复用，无需对每次合法派工重复询问。

启动顺序是：全层 `TEAM_READY` → 已有用户授权内的限定可行性试验许可 → 关键能力小样本或同环境有效原始证据核对 → 正式契约生效 → 产品实施。试验许可记录范围、预算、环境及停止条件，不要求被测能力已经成功，也不授权正式实施或交付；已有授权可直接引用，不新增重复确认。使用 [共同运行证据规则](runtime-evidence.md) 中的清单、冻结核对和检查汇总入口；工具仅核对机械证据条件。组建过程仍完整执行 AGENT-01，不能把业务小样本放到全员就绪之前。记录任务特征可帮助选择执行顺序与并行范围，不自动更换人类选定的治理模式。

### 方式 B：让 Codex 安装，再按名称引用

若希望通过技能选择器或名称调用，应先把三个技能文件夹完整放入同一技能发现目录，并验证各自 `SKILL.md` 的标准 YAML 元数据。官方文档列出项目级 `.agents/skills/` 和用户级 `$HOME/.agents/skills/`；新技能通常自动发现，未出现时可重启 Codex。此处仅说明方式，本次未执行安装或修改原有两个技能。[OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills)

**安装时发送给 Codex：**

```text
请将 E:/AIProject/GAS/GAS-Agent-Skills/ 中的以下三个技能完整安装到
我的个人技能目录 $HOME/.agents/skills/，保持三个文件夹同级：
- gas-combined-development
- gas-decentralized-development
- gas-centralized-development

请先检查目标目录是否存在同名技能，保留已有自定义修改；
检查安装副本的 SKILL.md 元数据格式、相对依赖和所有必需文件，
并报告安装路径及实际可核实的技能发现状态。
如果宿主需要重启才能发现，请明确告知，不把复制成功当作已验证加载。
```

Windows 下 `$HOME` 表示当前用户目录；在本机通常对应 `C:/Users/ruyangge`。安装需要遵守实际文件写入权限。组合技能通过同级相对路径读取另外两个技能，因此安装时应一并保留这两个依赖，不能只复制组合技能的 `SKILL.md`。

确认技能已被发现后，可以发送：

```text
请使用 $gas-combined-development 完成【任务】，
内层执行者数量为【N>=1，默认1】，先核实N+5个治理子agent及主会话（共N+6）的运行能力，
主会话不任任何治理角色，再按组合协议建立角色、契约和验收流程。
```

未出现在选择器时，仍可采用绝对路径读取方式，前提是当前 Codex 有该文件的读取权限。
