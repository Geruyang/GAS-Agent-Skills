# 组合开发模式：架构与 Codex 使用说明

![左侧为 Skill 架构，右侧说明直接读取、安装后引用和子 agent 并发配置](../assets/architecture-codex-guide-v3.png)

## 左侧：Skill 架构

**外层执行者与内层指挥者是同一身份、同一任期，只占一个席位。** 外层立规者制定规则和验收标准，裁衡者独立检查规则是否忠实于用户意图、成果是否满足有效规则；执行者在这些边界内自主组织实施。外层三方平级，宿主工具树上的父子关系不改变治理权力。

内层由这个执行者以指挥者身份管理：执行者实施和自测，审查者独立验证技术事实，监督者核对执行者与审查者的行为及指令理解。监督者不监督指挥者；指挥者作为外层执行席，仍受外层规则与独立裁衡约束。

青色双向箭头表示外层契约、复议和裁衡关系；蓝色向下箭头表示内层派工管理。下属报告向指挥者回流，以图下文字标注。裁衡者对立规规则的意图一致性审查也以职责文字说明。

交付顺序是：**内层接受 → 准备精确集成候选并完成必要重验 → 外层独立裁衡 → 获准交付。** 最终合并或发布由同一执行者兼指挥者完成，两层引用同一个真实动作和回执。图示是概览，具体规则以 [SKILL.md](../SKILL.md) 和 [组合协议](protocol.md) 为准。

## 右侧：在 Codex 中实施

图中方式 A 是直接读取文件，方式 B 是让 Codex 完成安装后按技能名称引用；二者均需在启动开发前核实角色、权限和席位。下文给出可复制的读取、安装和启动指令。

### 1. 在目标项目中按路径读取

当前文件位于普通项目目录，可以让具备文件访问能力的 Codex 直接读取。三个技能保持同级，组合技能的相对依赖才能解析：

```text
E:/AIProject/GAS/GAS-Agent-Skills/
├── gas-decentralized-development/
├── gas-centralized-development/
└── gas-combined-development/
    └── SKILL.md
```

本方式是让 Codex 读取并执行协议，不代表目录已经加入自动发现列表。当前已有文件可直接使用下面的完整提示词。

### 2. 复制启动指令

替换方括号中的任务信息后，在目标项目聊天中发送：

```text
请读取 E:/AIProject/GAS/GAS-Agent-Skills/gas-combined-development/SKILL.md，
以及其中要求读取的组合协议、同级分权和集权技能及其协议，
按组合开发模式完成【具体开发任务】。

主会话担任外层执行者兼内层指挥者。
请先核实子 agent 工具、实际并发上限及现有占用；能力足够时，
为外层立规者、外层裁衡者、内层执行者、内层审查者、内层监督者
各建立真实独立身份，并登记身份与职责。

允许修改：【文件或模块路径】。
验收标准：【可核验的行为、检查或测试】。
预算与停止条件：【时间、调用次数或其他可核对额度】。
本次仅授权本地修改与测试；合并、部署、发布需另有适用授权。

请遵循先立约、后实施、内层接受、候选验证、外层裁衡的流程。
若缺少角色或能力，请明确报告降级与缺口，只推进仍可安全完成的工作，
不要用同一会话切换称呼冒充独立角色。
```

### 3. 配置子 agent 并发上限并核实能力

本 Skill 完整默认配置需要 **1 个主会话 + 5 个子 agent**，共六个独立身份。六席是本协议要求，不是所有 Codex 环境的默认上限。Codex 的单会话子 agent 并发上限可以配置。

在项目的 `.codex/config.toml` 中添加或更新以下内容；若已有 `[agents]` 段，在该段内修改此键，不重复创建同名段：

```toml
[agents]
max_concurrent_threads_per_session = 16
```

`16` 是单会话中并发打开的子 agent 上限，不包含主会话，也不表示必须创建 16 个子 agent。本 Skill 默认只需五个子 agent，加上主会话形成六个身份。启动时核实配置已经生效、多 agent 工具可用、实际运行限制和现有占用；若多 agent 被显式禁用，还需按实际环境启用。配置不足或尚未生效时据实报告，不将文件中的数值当作已经验证的可用能力。[OpenAI：Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

本次只将该配置示例加入图片与说明，没有修改实际 `.codex/config.toml`。

### 4. 检查过程与结果

让 Codex 展示角色身份、有效契约与版本、精确候选、内层技术审查与监督事实、外层裁衡结论和实际交付回执。运行记录保存到目标项目内 `.gas/runs/<run-id>/` 或已获准的任务系统；`run-id` 是实际运行标识，不把尖括号当作 Windows 目录名。

分别报告自测、内层接受、外层验收、合并和发布状态。没有执行的步骤写“未执行”；缺独立审查或监督时保留等待状态。已有适用授权可复用，无需对每次合法派工重复询问。

### 方式 B：让 Codex 安装，再按名称引用

若希望通过技能选择器或名称调用，应先把三个技能文件夹完整放入同一技能发现目录，并验证各自 `SKILL.md` 的标准 YAML 元数据。官方文档列出项目级 `.agents/skills/` 和用户级 `$HOME/.agents/skills/`；新技能通常自动发现，未出现时可重启 Codex。此处仅说明方式，本次未执行安装或修改原有两个技能。[OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills)

**安装时发送给 Codex：**

```text
请将 E:/AIProject/GAS/GAS-Agent-Skills/ 中的以下三个技能完整安装到
我的个人技能目录 $HOME/.agents/skills/，保持三个文件夹同级：
- gas-combined-development
- gas-decentralized-development
- gas-centralized-development

请先检查目标目录是否存在同名技能，保留已有自定义修改；
检查安装副本的 SKILL.md 元数据格式、相对依赖和所有必需文件，
并报告安装路径及实际可核实的技能发现状态。
如果宿主需要重启才能发现，请明确告知，不把复制成功当作已验证加载。
```

Windows 下 `$HOME` 表示当前用户目录；在本机通常对应 `C:/Users/ruyangge`。安装需要遵守实际文件写入权限。组合技能通过同级相对路径读取另外两个技能，因此安装时应一并保留这两个依赖，不能只复制组合技能的 `SKILL.md`。

确认技能已被发现后，可以发送：

```text
请使用 $gas-combined-development 完成【任务】，
先核实六席运行能力，再按组合协议建立角色、契约和验收流程。
```

未出现在选择器时，仍可采用绝对路径读取方式，前提是当前 Codex 有该文件的读取权限。
