## 用户四点与落地

| 要求 | 本地修改 |
| --- | --- |
| 审查者接收执行者、监督者输出并分析问题，不编写测试／验证代码 | 集权审查者及组合内审、外裁明确不写或修改验证代码；分权裁衡者同样分析执行及可用监控证据。补证交具名执行者。审查可静态分析、对读证据及复跑已有获准命令；独立判断和精确候选门禁保留。 |
| 可由用户指定多名执行者，各自开发和验证独立工作 | 支持正整数 N，默认 1。执行者名单、任务、路径、验证代码与证据归属进入模板；集权 N+3、分权 N+2、组合内层 N 时 N+5 个真实子 agent，另加主会话。组合只保留一个外层执行者／内层指挥者桥接身份。 |
| 监督意图符合性及关键安全、运行和工作状态 | 集权与组合监督者对照指挥者意图覆盖全部执行者和审查者，监测板卡电压、电流、运行、agent 状态及软硬件异常，向指挥者汇报并供审查者分析。记录来源、单位、时刻、阈值、采样有效性和不可测项。分权保留三类平级职能，各执行者监控并共享自身事实，裁衡者分析异常。 |
| 指挥者尽量增加并行任务 | 集权与组合主动并行所有就绪独立任务；开发、各自验证、已有产物分析和监控可重叠。真实依赖、写入冲突、板卡烧录／调试等独占资源及预算只限制相关动作。分权平级执行者依有效契约协商分工，不新增指挥席。 |

## 覆盖与保留

修改三技能入口、完整协议、现行使用说明、运行／任务／审查／监督及证据复用模板、待运行场景；同步共享证据规范和根目录中英文角色图。离线检查增加人数类型、计划人数公式、配置来源、未执行示例归属及审查代码权限门禁，允许 N=3 的未批准配置正例。分权单执行人数限制改为实际 N 的容量与平级认领检查。

保留原运行 schema 3／2／1、共同 runtime schema 1，默认人数 4／3／6；AGENT-01 的配置与职责确认、等待、全员就绪和服务档位规则不变。主会话不任治理角色；原授权、独立审查、硬失败、预算、任期、未知副作用及发布门禁继续适用。

## 独立审查修正

只读审查者不编写测试代码。其基线指出分权唯一执行者硬冲突、监督范围及审查输出流向缺口；更新后复核提出以下修正，交维护执行者完成：组合继承表不再引用过时单执行原规则；监控增加采样与评估时间及有效窗口引用；普通执行者替换须核实旧写入／设备控制停止或撤权，不凭超时释放锁；单通道缺测阻塞相关动作，与监督角色整体失联区分。未知阈值、新鲜度或采样能力不改成正常／安全；暂停与断电等控制仍依据有效授权。
